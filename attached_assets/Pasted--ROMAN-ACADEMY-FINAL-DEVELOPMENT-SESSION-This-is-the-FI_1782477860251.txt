## Academic Workflow (WITH EXACT INPUT + SYSTEM FLOW)

### STEP 1 — Teacher Starts a Chapter

**INPUT SOURCE**

Teacher performs this action from:

→ **Teacher Dashboard → Chapter Progress Page**

Expected UI:

* Dropdown: Subject
* Dropdown: Batch
* Dropdown / Input: Chapter Name
* Button: "Start Chapter"

**FILES INVOLVED**

* Frontend Page: `TeacherChapterProgressPage`
* API Route: `/api/chapters/start`
* Backend Service: `chapterService.startChapter()`
* Database Table: `chapters`

**WHAT HAPPENS INTERNALLY**

When teacher clicks "Start Chapter":

1. A new record is created OR existing chapter updated:

   * status = ONGOING
   * start_date = current timestamp
   * subject_id
   * batch_id

2. Ensure:

   * Only ONE ONGOING chapter per subject per batch
   * Multiple subjects can have ONGOING chapters simultaneously

**WHAT MUST UPDATE IMMEDIATELY**

* Teacher Dashboard → Current Chapters Section
* Student Dashboard → "Ongoing Chapters"
* Student Notifications Table → New notification created
* Schedule Page → Reflect active chapter

---

### STEP 2 — Teacher Completes a Chapter

**INPUT SOURCE**

Same page:

→ **Teacher Dashboard → Chapter Progress Page**

Button:

* "Mark as Completed"

**FILES INVOLVED**

* Frontend: `TeacherChapterProgressPage`
* API: `/api/chapters/complete`
* Backend: `chapterService.completeChapter()`
* DB Tables:

  * `chapters`
  * `weekly_syllabus_pool`

**WHAT HAPPENS INTERNALLY**

1. Update chapter:

   * status = COMPLETED
   * completed_date = current timestamp

2. Automatically push chapter into:
   → Weekly Syllabus Pool

**WHAT MUST UPDATE**

* Weekly Test Page → Upcoming syllabus
* Student Dashboard → Completed Chapters
* Notification Engine → "Chapter Completed"
* Internal pool tracking

### STEP 3 — Weekly Test Flow

**INPUT SOURCE**

**FILES INVOLVED**

* Frontend: `UploadMarksPage`

* Backend: `testService.processWeeklyMarks()`
* DB Tables:

  * `test_results`
  * `leaderboard`
  * `student_stats`

**WHAT HAPPENS INTERNALLY**

System automatically:

* Calculates ranks
* Updates leaderboard
* Updates student performance stats
* Updates graphs data
* Updates weak/strong analysis

**SYLLABUS FLOW**

After Weekly Test:

→ Chapters used in Weekly Test move to:
**Monthly Syllabus Pool**

### STEP 4 — Monthly Test Automation

**NO MANUAL INPUT REQUIRED**

System must automatically compute:

Monthly syllabus = all chapters in Monthly Pool

**FILES INVOLVED**

* Backend: `syllabusService.getMonthlySyllabus()`
* DB Table: `monthly_syllabus_pool`

**AFTER MONTHLY TEST**

* Chapters move to:
  → Quarterly Pool

* Monthly Pool resets

### STEP 5 — Quarterly Test Automation

**NO MANUAL INPUT REQUIRED**

Quarterly syllabus = all chapters in Quarterly Pool

**FILES INVOLVED**

* Backend: `syllabusService.getQuarterlySyllabus()`
* DB Table: `quarterly_syllabus_pool`

**Quarter Definitions**

June + July + August → August End
September + October + November → November End
December + January + February → February End

**AFTER QUARTERLY TEST**

* Quarterly Pool resets
* Monthly Pool resets
* Weekly Pool resets

**IMPORTANT**

* DO NOT DELETE DATA
* Move data to history tables

## Chapter Logic

A chapter has only one truth.

PLANNED → ONGOING → COMPLETED

Only COMPLETED chapters enter Weekly syllabus.

Never use PLANNED or ONGOING chapters in tests.

Support multiple ongoing chapters simultaneously.
